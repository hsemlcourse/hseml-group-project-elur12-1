# Описание данных

## Источник

Датасет **TotalCapture** (CVSSP, University of Surrey): https://cvssp.org/data/totalcapture/

Из-за лицензии данные **не распространяются** в репозитории — папка `data/raw/` добавлена в `.gitignore`. Чтобы запустить пайплайн, скачайте архивы с сайта и разложите файлы по структуре, описанной ниже.

В рамках курсового проекта используется только **subject S1** (один человек, 12 записей-действий). Остальных субъектов (S2–S5) можно добавить аналогичным образом.

## Перечень действий (takes) для S1

Каждое действие записано всеми тремя источниками одновременно (Vicon + IMU + Gyro/Mag):

| Категория  | Записи                              | Краткое описание                                        |
|------------|-------------------------------------|---------------------------------------------------------|
| `acting`   | `acting1`, `acting2`, `acting3`     | Актёрские сцены (разнообразные позы и движения)         |
| `freestyle`| `freestyle1`, `freestyle2`, `freestyle3` | Произвольные движения, наиболее сложные для модели |
| `rom`      | `rom1`, `rom2`, `rom3`               | Range of Motion — плавные движения по полному диапазону суставов |
| `walking`  | `walking1`, `walking2`, `walking3`   | Ходьба (циклические движения)                           |

Итого **12 файлов на источник**.

## Структура `data/raw/`

```
data/raw/
├── s1_imu/             # IMU: ориентация (кватернион) + локальные акселерометры + калибровки
├── s1_Gyro_Mag/        # IMU: гироскопы + магнитометры (вспомогательные поля)
└── S1_vicon/           # Эталонные 3D-позы (ground truth) с системы Vicon
```

### 1. `s1_imu/` — основные IMU-измерения

Файлы `s1_<action>_Xsens.sensors` (12 шт.) — выходы Xsens MTw IMU. Формат:

```
[num_sensors]\t[num_frames]
[frame 1]
[sensor_name]\t[ori quat (w x y z)]\t[local accel (x y z)]
... (по одной строке на каждый из 13 сенсоров)
[frame 2]
...
```

- `num_sensors = 13` (см. таблицу IMU↔Bone ниже).
- Кватернион ориентации в **локальной системе IMU**, порядок `(w, x, y, z)`.
- Акселерометр — в **локальной системе IMU**, в м/с² (с гравитацией).
- Частота — 60 Гц (синхронизирована с Vicon).

**Калибровочные файлы** (по одному на действие):

- `s1_<action>_calib_imu_bone.txt` — оффсет «IMU → Bone» (R_ib): как IMU развёрнут относительно кости.
- `s1_<action>_calib_imu_ref.txt` — оффсет «IMU reference → Global» (R_ig): связь референсной системы IMU с глобальной системой Vicon.

Формат калибровки (внимание — порядок кватерниона **`(x, y, z, w)`**, отличается от `.sensors`):

```
[num_sensors]
[sensor_name]\t[ori quat (x y z w)]
...
```

Глобальная ориентация кости вычисляется как:

```
R^g_b = R_ig · R_imu · (R_ib)^(-1)
```

### 2. `s1_Gyro_Mag/` — гироскоп и магнитометр

Файлы `<Action>_Xsens_AuxFields.sensors` (12 шт.). Формат как у `.sensors` из `s1_imu/`, но содержит **дополнительные поля**:

```
[sensor_name]\t[ori quat (w x y z)]\t[local accel (x y z)]\t[gyro (x y z)]\t[mag (x y z)]
```

То есть здесь есть **все 13 каналов на сенсор**: ориентация (4) + акселерометр (3) + гироскоп (3) + магнитометр (3). Эти файлы парсятся как «полный» источник IMU-фичей.

> Замечание: `s1_imu/*.sensors` и `s1_Gyro_Mag/*.sensors` относятся к одним и тем же кадрам — `s1_Gyro_Mag` это просто расширенная версия. В коде используем `s1_Gyro_Mag` как основной источник IMU-фичей, а калибровки берём из `s1_imu/`.

### 3. `S1_vicon/` — ground truth (целевые переменные)

Файлы `<action>_BlenderZXY_YmZ.bvh` (12 шт.) — мокап-данные с Vicon, экспортированные в формат **BVH** (Biovision Hierarchy) с конвенцией поворотов **ZXY** и заменой осей **Y → −Z** (под Blender).

BVH содержит:

- **HIERARCHY** — иерархия скелета (имена костей, оффсеты от родителя в T-позе).
- **MOTION** — для каждого кадра: глобальное положение Hips (3 числа) + углы Эйлера (ZXY) для каждой кости (по 3 числа).

Из BVH вычисляются **глобальные 3D-позиции суставов** (forward kinematics) — это и есть таргеты регрессии. Частота — 60 Гц, синхронизирована с IMU по числу кадров.

## Соответствие IMU ↔ кость скелета

13 сенсоров крепятся к следующим костям:

| IMU         | Bone (BVH)      |
|-------------|-----------------|
| Head        | Head            |
| Sternum     | Spine3          |
| Pelvis      | Hips            |
| L_UpArm     | LeftArm         |
| R_UpArm     | RightArm        |
| L_LowArm    | LeftForeArm     |
| R_LowArm    | RightForeArm    |
| L_UpLeg     | LeftUpLeg       |
| R_UpLeg     | RightUpLeg      |
| L_LowLeg    | LeftLeg         |
| R_LowLeg    | RightLeg        |
| L_Foot      | LeftFoot        |
| R_Foot      | RightFoot       |

## Постановка задачи ML

- **Вход (X)**: для каждого кадра — 13 сенсоров × (4 quat + 3 accel + 3 gyro + 3 mag) = **169 фичей** на кадр (плюс производные velocity-фичи).
- **Выход (Y)**: 3D-позиции набора целевых суставов (например, верхняя часть тела: Spine, Spine1–3, Neck, Head, Shoulders/Arms/ForeArms/Hands — 14 суставов × 3 = 42 числа на кадр) либо все 23+ сустава скелета.
- **Метрика**: **MPJPE** (Mean Per-Joint Position Error, мм) — основная; RMSE/MAE — вспомогательные.

## Сплит train / val / test

Чтобы избежать **data leakage** (соседние кадры одной записи почти одинаковые), сплит делается **по записям (takes)**, а не по кадрам:

- **train**: `acting1`, `acting2`, `freestyle1`, `freestyle2`, `rom1`, `rom2`, `walking1`, `walking2` (8 записей)
- **val**: `acting3`, `walking3` (2 записи)
- **test**: `freestyle3`, `rom3` (2 записи) — финальная оценка качества

Такой сплит покрывает все четыре типа активности и в train, и в test.
